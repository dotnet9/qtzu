# 每关跳跃玩法 + UI 换皮（开源免费、体验优先）

前置：`main` @ `d9c89c8`。本方案回应两条真实反馈：**朋友**"UI 太丑、没法商业化"、**小朋友**"能加跳跃玩法吗？比如跳云梯到高点台子上再放蛋"。

用户已明确的取舍：
- **不付费**（开源免费玩），"商业化"= **能上架/能展示**
- 重点是**玩法与画质向收费 3D 游戏靠拢**、**用户体验优先**
- UI 走**重新设计视觉语言（换皮）**，不是小修
- 顺序：**先做每关跳跃玩法**（用户选 1），UI 换皮随后

## 一、调研结论（都是代码里核实过的，不是推测）

### 1.1 小朋友要的玩法**已经有了，但只在农场岛**

| 玩法 | 位置 | 参数 |
|---|---|---|
| **9 级跳跳云梯 → 天空岛**（云朵上下浮动） | `js/world.js:930-954` | 台面 1.3 → 12.4，逐级 +1.3；`world.anim.cloudStair` 驱动 `bob` |
| **三级跳跳石 + 高台（台顶放蛋）** | `js/world.js:976-995` | 1.0 → 1.85 → 2.75；`world.perch` → 每关一颗蛋 |
| **悬浮砖块**（顶爆掉蛋，可站上去） | `js/world.js:906-928` | `addPlatform(b.x, b.z, 0.55, b.top)` |
| 提示文案（已写好多语言） | `data/i18n/ui.zh.json:112,181` | "⬆️ 这颗蛋在高台顶上，踩着石头跳上去！" |
| **城市模式** | `js/world.js:1646-1650` | 只有**一个观景石台**（顶面 `Y+3.45`），每关轮换一颗蛋上去 |

### 1.2 跳跃力学（决定"几级台阶才跳得上去"）

`js/game.js:719/723/2702`：起跳 `vy=8.6`、二段 `vy=max(vy,0)*0.4+7.6`、重力 `20`。

- 单跳高度 **8.6²/40 = 1.85**
- 二段跳总高度 **≈ 3.30**
- 台阶递进必须 **≤ 1.5**（留 20% 容错，孩子手速慢）；**3.45 的台子必须二段跳或从高处起跳**——这正是现有城市石台"够不着"的原因（`game.js:758` 的提示"⬆️ 这颗蛋在高台顶上"就是这么触发的）

### 1.3 关卡数（决定"每关加多少内容"）

`js/words.js:717/720/759`：`PER_CHAPTER=6`；一关 = **6 个新词 + 6 个复习词**；序章（农场/海滩/森林）`PROLOGUE_CHAPTERS = ceil(60/6) = 10` 关；之后按本册词表继续切（3a/4a/5a 等）。**所以"每关"是几十关的量级** → 必须**程序化生成**，不能手工摆。

### 1.4 平台/地形基建（已就绪，不用新写）

- `js/world.js:624` `colTop(x,z,r,top,bottom,bounce)`：登记"可站立 + 挡路"的台面
- `js/world.js:629` `addPlatform(x,z,r,top)`：只登记可站立（云朵这类软物件）
- `js/game.js:2849` `_platformAt` / `:2862` `_supportAt`：落足判定（含 `pf.top <= y + 0.3` 的容差）
- `js/game.js:2875` `_groundY(x,z)`：城市微缩地形高度（**台阶必须叠在地形之上**，否则山坡上的台阶会浮空/埋进山）

### 1.5 画质现状（回答"向收费 3D 游戏靠拢"）

已做：ACES 色调映射（`game.js:203`，曝光 0.98）、SMAA、PMREM 环境反射（仅桌面）、辉光（0.22/0.5/0.98）、烘焙硬棱 + 顶点色 AO、贴图化地面、InstancedMesh 散点。

**与"收费 3D"差距最大的三处**（按投入产出排序）：
1. **没有接触阴影**（`_groundY` 只用于贴地，角色脚下没有软阴影）→ 收费 3D 的"落在地面上"的第一观感
2. **天空是静态渐变**（`world.js:636-647`）→ 缺体积云/日夜过渡
3. **没有后处理氛围**（无 DOF/暗角/色彩分级 LUT）→ 画面"平"

### 1.6 UI 现状（"丑"的根因之一已定位）

- **确定的缺陷**：`css/style.css:14` `--c-primary-soft: var(--c-primary-soft);` —— **变量自我引用**（CSS 计算时构成循环 → 失效）。它有 6+ 处用途（`:115/:381/:463/:584/:1213`…），所以**所有"选中态浅粉底"都失效**，控件看起来像"没选中/裸的"。这就是"丑"的直接来源之一。
- 量级：`style.css` **116KB / 1893 行 / 200+ 处硬编码色值**（token 有定义但没强制用）；8 个全屏面板（`index.html` 的 `#profile/#pet-card/#modal/#picker/#catalog/#map/#intro/#levelup`）+ 7 个 UI 模块各自写样式。
- 已有 token 体系（`--c-primary/--c-text/--c-surface/--grad-cta/--r-card/--shadow-pop`…）—— 换皮应**在这套 token 上重构**，而不是推倒。

## 三、阶段一：每关跳跃挑战（先做）

### 3.1 抽成可复用摆放函数（`js/world.js`）

新增 `placeJumpChallenge(scene, grp, spec, helpers)`，参数化生成三类挑战（沿用现有造型与配色）：

| 类型 | 造型 | 台面序列 | 蛋位 |
|---|---|---|---|
| `stairs` | 石阶（现有 `CylinderGeometry` + 现有配色 `#BCC8B4/#9FB894`） | 3~4 级，递进 1.3~1.5 | 顶台 |
| `bricks` | 悬浮砖块（现有造型） | 单块 / 两块递进 | 砖块内部（顶爆掉落） |
| `cloudStair` | 云朵（`PROPS.cloud`，带 `bob` 浮动） | 4~6 级 | 顶台（更高、更"贵"） |

**关键约束**：
1. 台面高度一律 `colTop(x, z, r, Y(x,z) + h)` —— **叠在城市地形之上**（`Y = _groundY`），否则山坡上会浮空
2. 摆位复用城市已有的避让链：`clampPoly(polySim, ...)` 钳制进轮廓 → `spot()` 避地标/树/主街 → `colC` 加碰撞
3. 每级之间水平间距 1.4~1.8（跳跃水平速度 `PLAYER_SPEED*1.38`，够跨）
4. 每城**总数上限 2 处**（1 处高台 + 1 处砖块），避免拥挤与碰撞体膨胀

### 3.2 按关卡轮换（`js/game.js`）

- 现状：`_perchEggId()`（`:491`）每关轮换一颗蛋上**固定的观景石台**；`_brickEggId()`（`:499`）轮换一颗进砖块
- 改为：**每关按 `chIdx` 选一处挑战类型 + 一处位置**（用 `makeSeedRand(昵称+册+关号)`，跨会话一致，与 `chaptersFor` 同口径）
- 蛋位来源仍是"本关 6 个新词里挑一个"，不新增词表负担

### 3.3 引导（让玩法"被发现"）

现有引导链（`game.js:1097-1199` 的 `_guideStep`）已包含"高台蛋"提示。补两点：
1. 每关**首次进入**时，若该关有跳跃挑战且蛋未取，弹一次带箭头的气泡指向挑战（复用现有 `_guideStep` 的 target 机制）
2. 跳上顶台时给一次**正反馈**（现有 `ui.cheer` + 星星），并在顶台放一个小奖杯/旗子（可复用 `PROPS`）

### 3.4 验收

- `scripts/verify-jump.mjs`（新）：对 52 城 × 每城抽 3 关，**逐级模拟跳跃可达性**（用真实的 `vy/g` 公式算可达高度，断言每级 ≤1.5 且顶台可达），并断言"每关至少 1 个蛋在平台上"
- 巡城 52 城 0 错误；帧时长不劣化（挑战数量少、几何便宜）
- **截图**：本轮浏览器可用 → 用 `look-shot.mjs` 的机位 + 新增 `jump` 机位（正对挑战，看台阶与蛋）

## 四、阶段二：UI 换皮（视觉语言重做）

### 4.1 设计方向（"向收费 3D 游戏靠拢"的 UI 语言）

保留"糖果卡通风"的**亲和力**（目标用户是小学生），但把"廉价感"去掉：

| 维度 | 现在 | 换皮后 |
|---|---|---|
| 层级 | 面板都是"白卡 + 圆角 + 粉阴影" | **三级层次**：底（场景模糊）/ 中（卡片：厚边 + 内高光）/ 顶（弹层：投影 + 背景压暗） |
| 描边 | 无统一描边 | **统一 2px 深色描边**（与 3D 侧的"硬棱"呼应，卡通手办的视觉语言） |
| 圆角 | `--r-card: 24px` 单档 | 三档：`--r-lg: 28px`（弹层）/ `--r-md: 18px`（卡片）/ `--r-sm: 12px`（控件） |
| 按钮 | 渐变 + 阴影 | **拟物按压**：顶面高光 + 底部厚边（按下时厚边变薄 + 下移 2px）—— 收费手游的标准手感 |
| 字体 | 系统圆体 | 保留圆体，但**固定字阶**（32/22/17/14/12）+ 标题渐变字 + 数字用等宽（星星/分数对齐） |
| 动效 | 简单 transition | **统一曲线**（`cubic-bezier(.34,1.56,.64,1)` 回弹）+ 面板进入 120ms 上浮 + 按钮 90ms 按压 |
| 图标 | emoji 混用 | 统一 emoji 尺寸/基线（`font-size` + `line-height` 归一），关键操作配 SVG 图标 |

### 4.2 实施要点（可验证）

1. **修掉失效变量**：`--c-primary-soft` 自我引用 → 改为具体值 `#FFE3EF`；全库扫一遍 `var(--x): var(--x)` 这类循环（写进 lint 脚本）
2. **token 强制化**：新增 `scripts/lint-css.mjs`：统计 `style.css` 里**非 token 定义处的硬编码色值**，目标从 200+ 降到 0（逐步替换，脚本给出清单）
3. **抽公共组件**（`css/style.css` 顶层 + `index.html` 的类名不动，避免破坏 `js/ui.js` 的 32 个 id 契约）：
   - `.card`（弹层卡）/ `.btn`（主/次/危险三态）/ `.chip`（标签）/ `.field`（输入）/ `.toast`
   - **不重命名现有 id**（`js/ui.js:32` 等有硬编码 id 列表，重命名会连带动 7 个模块）
4. **8 个面板逐一换皮**：`#profile` → `#intro` → `#pet-card` → `#modal` → `#picker` → `#catalog` → `#map` → `#levelup`（按使用频率排序）
5. **可访问性**：对比度 ≥4.5:1（正文）、点击区 ≥44px、`prefers-reduced-motion` 下关闭回弹

### 4.3 验收

- **逐面板截图对比**（本轮浏览器可用）：换皮前/后各一张，`scripts/compare.mjs` 合成对比图
- `lint-css.mjs`：硬编码色值 0 处、变量循环 0 处
- 视口矩阵：**手机竖屏（360×740）/ 平板（768×1024）/ 桌面（1280×760）** 三档都截图（收费游戏的 UI 必须在三档都不破）
- `test-fallback` + 巡城不退化（UI 改动不该影响玩法）

## 五、阶段三：画质靠拢（接触阴影 + 天空 + 后处理）

| 项 | 做法 | 代价 |
|---|---|---|
| **接触阴影** | 每个角色/词宠/NPC 脚下加一张软阴影贴片（`CanvasTexture` 径向渐变，`depthWrite:false`），半径随跳跃高度缩小 —— 这是"落在地面上"的关键，也是收费 3D 的标配 | 每实体 +1 个 quad；用 InstancedMesh 或共享贴图，几乎无成本 |
| **天空体积云** | 现有渐变穹顶 + 2~3 层视差云（`PROPS.cloud` 的贴图平铺在穹顶上，缓慢平移） | 1 个额外材质；触屏关 |
| **轻后处理** | 暗角（`vignette`）+ 色彩分级（一张 16×16×16 的 LUT，或直接用 `ShaderPass` 做 lift/gamma/gain） | 复用现有 composer 链，+1 pass |
| 地面湿滑/雪地反光 | 已有 `_waterAt/_onSnow` 判定 → 对应区域提高 `roughness` 对比 | 小 |

验收：`check-render` 全绿（**注意**：暗角会改变上缘/草地亮度采样，需同步校准阈值）、帧时长 ≤ 基线 5%、截图对比。

## 七、风险与边界

1. **台阶叠地形**：城市有微缩地形（`_groundY`），台阶必须 `Y+h`；否则山坡上的台阶会浮空或埋进山。`verify-jump.mjs` 逐级校验时会一并检查"落点高度 = 平台顶面"。
2. **碰撞体预算**：现 212（上限 260）。每城 +2 处挑战（各 3~4 个台面）→ 会超。**对策**：挑战台面用 `addPlatform`（只登记可站立、**不进碰撞体**），侧面阻挡交给地形/已有碰撞；或把上限提到 320 并说明。
3. **UI 换皮不破坏 `js/ui.js` 契约**：32 个 id 与 7 个模块硬编码，**只改样式与结构包裹，不改 id/类名语义**。
4. **后处理影响体检阈值**：暗角/LUT 会改变亮度统计，`check-render` 的阈值要同步校准（否则"画面变好看"会被判成不达标）。
5. **不付费 = 无合规负担**：本方案不涉及内购/订阅/家长同意；分享链接（`game.js:900`）与家长周报（`ui.js:1448`）已存在，属于"能展示"的部分，不扩展。
6. **帧率红线**：本机 iGPU 实测 16.70ms（60fps 上限）；接触阴影+云+后处理都会吃预算 → 每步都必须回跑 `look-shot` 的帧时长中位数，超 5% 就退档（触屏一律关）。
7. **我看图的能力刚恢复**：本会话第一次能用浏览器（`browser_open` 成功、拿到了档案页截图）。**但我的工具没有点击/输入**，所以只能截"直接可达的页面"（档案页、以及我造的固定机位图）；**面板内部状态**需要你点开截图，或我加"用 URL 参数直接打开某面板"的调试开关（建议加，代价很小）。
