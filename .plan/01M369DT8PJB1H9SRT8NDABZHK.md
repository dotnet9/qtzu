| 我曾说 | 事实 |
|---|---|

## 一、HUD 游戏化（最大收益 / 最低风险）

### 1.1 参考图的 HUD 语言 → 本作映射

| 参考图 | 本作对应 | 数据来源（现成） |
|---|---|---|
| 顶部血条 + 条内 `110 / 110` | **主进度条**（条内数字 `3 / 6`） | `updateHUD(count, total, …)` |
| 条下细条（经验） | 条下 2px **星星细条**（本关星星占比） | `setStars(n)` |
| 等级标题 `炼气期` + `修为 0/10` | 条下小字：`第 1 关`（章节） | `updateHUD` 的 `chapterText` |
| 技能图标 + 冷却计数 | **词宠头像栏**：本关随行的 6 个词宠，未收集为虚线空槽 | `petThumbnail()`（已有，384px） |
| 右上 4 枚色块堆（击杀/波次/时辰/最高） | 右上 4 枚色块：`⭐ 星` / `🏆 分` / `🥚 蛋 n/m` / `🔥 连击` | 星=save、分=sessionScore、蛋=关卡、连击=streak |
| 右下暂停圆钮 | 沿用 `☰`（**不加独立暂停键**，避免与菜单重复） | — |

### 1.2 关键约束：**保留 4 个 id 与"数据锚点"语义，不换 id**

这 4 个 id 不只是显示，它们被别处引用：

- `js/ui.js:835` `homeStars()` → 把星星**飞进** `#star-pill` 的 `getBoundingClientRect()` 中心
- `js/ui.js:1525` `homePaw()` → 把爪印**飞进** `#pet-count` 中心
- `js/ui.js:143` `#star-pill` 上有 **click 监听**（点开星星说明）
- `style.css:1610` `body.has-hungry #score-pill{display:none}`、`style.css:172` `body.fever #score-pill`

→ 所以：**保留 `#pet-count` / `#star-pill` / `#score-pill` / `#hungry-pill` / `#user-pill` 五个 id 与可见尺寸**，
只改它们的**外观与内部结构**，把它们从"药丸"升级成参考图那种"条/角标/图标栏"。

### 1.3 必须同步改的三处写入者（否则会把自己的子元素擦掉）

现有写入者用的是 `textContent = …`，那会**清空容器内的所有子元素**。改了内部结构后必须改为写内层 span：

| 位置 | 现在 | 改为 |
|---|---|---|
| `js/ui.js:101` `renderPetCount()` | `els.petCount.textContent = …` | 写 `#pet-count-text`（新增内层 span） |
| `js/ui.js:139` `setStars()` | `els.starPill.textContent = '⭐ n'` | 写 `#star-pill-num` |
| `js/ui.js:1857` | `els.scorePill.textContent = …` | 写 `#score-pill-num` |
| `js/ui.js:16` 的 `els` 列表 | — | 追加 `pet-count-text` / `star-pill-num` / `score-pill-num` / `pet-icon-bar` / `hud-chapter` |

（这是本轮**唯一**有"静默坏掉"风险的地方：漏改一处，文字会消失或动画飞到 (0,0)。放进校验。）

### 1.4 结构与样式

- `index.html` `#hud-left`：主进度条容器（`#pet-count`）+ 条下小字（`#hud-chapter`）+ 词宠头像栏（`#pet-icon-bar`）
- `index.html` `#hud-right`：改为 `.hud-chip` 色块堆（`#star-pill` / `#score-pill` / `#egg-chip` / `#streak-pill`）
- `css/style.css`：新增 `--hud-chrome`（半透明深色 `rgba(28,22,18,.42)` + 1px 高光 + 圆角 10px + 内阴影），
  与参考图一致；**彩色填充仍用现有马卡龙渐变**（保留糖果感）
- **手机融合规则要一起改**：`style.css:1631-1633` 现在把两枚药丸拼成一枚，新结构下改为
  "进度条占满一行 + 色块堆折成两行"
- 词宠头像栏：`petThumbnail(id)` 的 dataURL 作为 `<img>`，收集=彩色，未收集=虚线空槽 + 灰度
  （缩略图是 LRU 60 的，6 个图标不会撑爆缓存）

### 1.5 反向进度：让"进入新关卡"看得见

## 二、斑驳光影（参考图最有识别度的光感）

### 2.1 做法：把光斑**烘进已有的 1024² 区域色贴图**（静态，运行期零成本）

- 新函数 `js/textures.js` → `dappleField(x, z, out)`：低频值噪声（`terrain-field.js` 已有 `n2(x,z)`，复用）
  生成 8~25 世界单位的柔和亮/暗斑块，幅度 **±8%**，只作用在**非水面**区域
- `js/terrain-field.js` 的 `zoneColor()` 末尾（`js/terrain-field.js:303` 那一段）乘上光斑系数
  —— 这是**唯一**的真源：顶点色路径 `zoneColorLinear`（`:299`）与贴图路径 `buildRegionTexture`（`terrain.js:288`）
  都调用它，所以两条路径自动同源，不会出现"触屏与桌面亮度不一致"的旧坑
- 为什么选这里而不是平铺贴图：区域色贴图**全城一次性映射、不平铺**（`terrain.js:298` mipmap 关闭），
  所以光斑是**大尺度的、不重复的**，正是参考图的观感；平铺的 `grassDetail`（`UV_TILE=4.5`）会每 4.5 米重复一次，读起来是花纹不是光影

### 2.2 为什么不做"缓慢漂移"（诚实说明）

漂移需要 `regUv` 加时间偏移，而那是一次性映射到城市包围盒的 —— 偏移后贴图会在 UV 边界出现**可见接缝**；
而且光斑一旦动起来，玩家会把它读成"云影"而不是"树影"，反而更假。
若做完全部五条后仍觉得地面太"死"，再单开一项（记在"未做"里）。

### 2.3 强度以现有门槛为准（用户选"保留明亮"）

- 目标：`grassLum` 落在当前区间内、**不得向 0.70 上界推**（`check-render.mjs:38` 上界 0.70；
  当前实测 0.668，已经贴近上界）→ 光斑**亮部幅度必须小于暗部**（亮 +3% / 暗 −8%），净效果是**略变暗**
- `grassSat` 下界 0.30（当前 0.406），光斑不得让草地发灰

## 三、地面彩绘升级（给已有铺装加材质层）

在 `js/terrain-field.js` 的 `zoneColor()` 里、主街/广场遮罩（`:341` 起）**之后**追加：

| 层 | 内容 | 参数 |
|---|---|---|
| 石板分格 | 沿主街方向的**缝**（周期性暗线 + smoothstep 软化），缝宽约占格宽 6% | 格宽 ≈ 2.2 单位（与参考图石板近似） |
| 裂缝 | 稀疏细枝状暗纹（用 `n2` 的高频脊线，阈值取 8%） | 幅度 −12%，只在广场/主街 |
| 苔藓 | 石板缝附近的**冷绿**斑（低饱和绿，只加在缝的邻域） | 幅度 +6%，色相偏冷以和草地分开 |
| 车辙 | 主街**中心**两条平行暗带（沿街方向长、跨街方向窄） | 幅度 −6% |

**必须保持同源**：三处实现都不能各写一套（历史上因为"顶点色 vs 贴图两条路径不同源"吃过亏 ——
`satur+60%/lum-10%` 那两次事故，注释都还在）。所以规则是：**只改 `zoneColor()` 一处**，
`zoneColorLinear()` 与 `buildRegionTexture()` 都只是它的调用者。

**性能**：只在 1024² 的一次性生成里多几次噪声采样（`buildRegionTexture` 只在进城时跑一次，触屏跳过），
**运行期 0 成本**。风险是生成时间：105 万像素 × 多一层噪声 ≈ 慢 30~60ms（进城一次，可接受；记进性能验收）。
