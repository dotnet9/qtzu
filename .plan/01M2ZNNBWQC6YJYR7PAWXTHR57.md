### 参考图观感的拆解（要复刻的四件事）

1. **边缘定义**：每个物体都有干净、连续的轮廓，物体与物体之间不糊在一起。
2. **明确的接触阴影 + 深浅分明的大色块**：物体"坐"在地面上，明暗反差强，不是一片均匀亮。
3. **高饱和的马卡龙/塑料玩具色 + 局部高光**：颜色干净、发亮但不发白。
4. **低角度、主体大、纵深深**的构图。

## 二、现状（已逐项核实，含本轮新发现）

### 2.1 你已经修好的（本方案不动，且后续改动不得回退）

- `js/game.js:245-252`：composer 末尾补 **`OutputPass`**。这是"发白"的根因——RenderPass 写进 RT 的是未 tonemap 的线性值，缺 OutputPass 时 UnrealBloomPass 会把线性辉光直接叠在已编码底图上，再加自身重绘底图那一步的编码差异 = 一片白雾。注释里已写清。
- `js/game.js:258-275`：`RoomEnvironment` 从**源头**乘 `ENV_ROOM_DIM`（`scene.environmentIntensity` 在 r160 不存在，r163 才有）。并已实测记录：环境全强度时草地饱和 0.22、关掉 0.31。
- `js/game.js:243`：辉光收到 `0.10 / 0.45 / 0.92`；`:196` 曝光 `0.98`；`:3341` 雾色改为浅蓝 `0xCBE6F2`（原近白雾色是发白主因之一）。
- `js/terrain-field.js:19`：顶点色按**线性值**处理（three r152+ 的口径）。

### 2.2 我实测看到的三个清晰度缺口（本方案的主攻方向）

| 缺口 | 证据 | 影响 |
|---|---|---|
| **post 路径把 MSAA 吃掉了** | `js/game.js:185` 给 renderer 开了 `antialias: true`，但桌面端走 `EffectComposer`（`:237-254`）：three 里 `antialias` 只作用于"渲染到默认帧缓冲"，经 composer 的离屏 RT 后失效，而 r160 的 `EffectComposer` 默认 RT **没有 samples** | 桌面端全屏锯齿（树冠、屋檐、栏杆最明显），越"精致"的模型越显脏 |
| **阴影框固定 ±60 且不跟随** | `js/world.js:579-583`：`mapSize 2048`、`shadow.camera = ±60`、无任何 `sun.target` 跟随代码；而成都舞台 `r = 87`（实测 `_currentStage().r`），北京更大 | 城的外圈**一点投影都没有**；2048 铺在 120×120 上约 17 texel/单位 → 接触影糊、没有"坐在地上"的分量感 |
| **资产全是"全平滑着色 + 弱 AO"** | `scripts/bake/common.py:349-351`：所有面 `use_smooth = True`（倒角段 2 段）→ 方盒被"吹圆"；`AO_STRENGTH 0.9 / AO_SKY 0.16`。我拍的对照图 `.cache/shots/gate-chengdu-pair.png` 里，梁/柱是模糊的圆边，没有瓦垄、门钉、台阶这类"读得出工艺"的构件 | 主体读起来"方盒拼装 + 模糊"，与参考图的干净轮廓相反 |

补充事实：画面里**占面积最大的是城市本体**（树/楼/地面/街道家具），校门只占一小块——`js/world.js:1504-1600`（绿化树丛 + 中环低模高楼）、`js/world.js:293 cityIslandTexture()`（城市地面 canvas 贴图）、`js/models/props-nature.js`（tree/pine/bush/…）。

## 四、技术设计

### 4.1 阶段一：渲染层清晰度（不换模型，先把"清晰"做出来）

1. **MSAA 走 composer**（`js/game.js:237-254`）
   - `new EffectComposer(renderer, new THREE.WebGLRenderTarget(w, h, { samples: 4, type: THREE.HalfFloatType }))`（r160 支持 RT 的 `samples`，需 WebGL2）；`lowEnd` 时维持现状（不进 composer）。
   - 另外按 `devicePixelRatio` 决定是否再叠一道 **`SMAAPass`**（`dpr < 1.5` 时开，`dpr >= 2` 时关，避免重复抗锯齿白付性能）。
   - 像素比保持 `min(dpr, 2)`；新增"post 路径下 `antialias` 无效"的注释，免得后人再踩。
2. **阴影跟人 + 分辨率**（`js/world.js:566-587` + 每帧更新）
   - `scene.add(sun.target)`，把 `sun.target.position` 设为玩家位置（或相机焦点），阴影框改为**跟随的小框**：`camDist ≤ 20` 时 `±22`，之后随 `camDist` 线性放大到 `±95`（保证拉远看全景时全城都有影）；`sun.shadow.camera.updateProjectionMatrix()` 只在需要时调用。
   - `mapSize` 桌面 `2048` → `4096`（帧时长不达标就退回 2048 并缩小框）；`radius 6 → 3`（框小了，不必再靠 radius 糊）；`bias -0.0004` 重调，消掉自阴影条纹。
   - 依据是 `js/world.js:582` 现在的 `far = cityOnly0 ? 400 : 110` 与城半径 87 的关系：小框跟随比大框铺满更省更清晰。
3. **边缘定义（描边）**：分两档，默认只开第一档
   - **A. 反向扩边（默认开，桌面端）**：给"关键主体"（玩家/词宠/NPC/校门/地标/街道家具）加一层背面外扩的墨色壳：`side: BackSide`，顶点沿法线外扩 `0.012` 世界单位，颜色 `#3A3340`，`depthWrite` 保持。实现放在 `js/assets.js` 的换装回调旁 + `js/models/kit.js` 的角色/词宠构建处，几何共用（同族实例不涨显存）。
   - **B. 深度边缘后处理（默认关，可开关）**：`ShaderPass` 做 Sobel（深度+法线），用来给"地面与建筑之间"补边；默认关是因为它在斜面上容易起噪点，留作调参项。
   - 触屏档：A/B 都关。
4. **分级调色**（新增一个 `ShaderPass`，放在 OutputPass 之前）：饱和度 +8%、S 曲线对比 +4%、高光偏暖 `(1.02, 1.00, 0.98)`、阴影偏冷 `(0.98, 0.99, 1.04)`。目的是把"干净发亮"和"发白"分开——发白是低对比 + 高亮度，干净是**高饱和 + 有黑位**。
5. **相机默认（按参考图）**：`camPitch 0.42 → 0.30`、`camDist 8.5 → 6.6`、`FOV 46 → 42`、`lookAt` 高度 `+1.0 → +0.88`（`js/game.js:201`、`:277`、`:3013`）。
   - 保留：缩放范围 `2.8~550`、双击拉远、触摸双指缩放、`_citySpawnPos` 的进城门 hero 机位（hero 用 `pitch 0.22 / dist 9`）。
   - 风险控制：视野变小 → 用 `_occlusionK` 的既有遮挡收缩逻辑兜底，并在 `perf-shot` 里对比"可见物体数"避免把该看见的挡掉。
6. **雾与天空**：`scene.fog` 保留你改的浅蓝，但把 `near` 抬高（`game.js:3057` 的 `max(fogR*1.35, 34+dist*2)` → 起雾更远），并把天空穹顶颜色改成"上深下浅"的双色渐变（参考图的天空是明显渐变），避免"远处一片同色"。

### 4.2 阶段二：城市本体（画面占比最大，收益最大）

1. **地面**（`js/world.js:293 cityIslandTexture()`）
   - 画布分辨率 `→ 1024`；内容从"纯色 + 噪点"升级为：**铺装广场（中心）/ 街道（迎宾主街）/ 草地分区 / 路缘石白线 / 排水沟 / 井盖 / 落叶点**；城市主色仍取 `city.color`，但整体**降亮提饱和**（当前接近纯白是"发白"的第二来源）。
   - 增加一张**细节叠加贴图**（128px 无方向噪点，`repeat` 平铺，`roughnessMap` 复用同一张），让地面在近景有"材质"而不是塑料板。
2. **绿化与高楼**（`js/world.js:1504-1600` 的摆放 + `js/models/props-nature.js` / `props-build.js` 的造型）
   - 树：从"一个大球"改为**分层树冠**（3~5 个错位球 + 主色/受光色/暗部色三色阶）+ 带倒角的树干 + 一级枝；`tree(blossom)` 保留两种变体。
   - 灌木/松/竹/花丛/岩石：同类做法（法线按角度硬化 + 三色阶 + 小倒角）。
   - 高楼：从"纯色方盒"改为**有门窗阵列、屋顶挑檐、女儿墙、雨棚、招牌、空调外机**的低模楼；提供 6~8 个原型（按城市色着色），按 `spot()` 摆放。
   - 街道家具（新增，按城市类型决定有没有）：路灯、长椅、花箱、指路牌、邮筒、遮阳伞、摊位。这些是"城市感"的主要来源，也是参考图里最抓眼的东西。
   - 摆放密度：绿化 `min(180, r*2.4)` 不变，但每棵树三角面上升 → 用 **InstancedMesh 或共享几何**（同原型只保留一份几何 + 材质，多个 `Mesh` 复用），必要时按距离做 per-city LOD（近岛精建、远岛用现有轻量占位）。
3. **天空/远景**：天空穹顶渐变（见 4.1.6）；远处邻城保持现有轻量占位，但把"地图纸面"的亮度压下去，让当前城是视觉焦点。
4. **贴图规格**（你说的"小尺寸贴图"）
   - 地面 1024×1024 PNG ≈ 150~400KB；建筑立面 256×256 × 6~8 张 ≈ 60KB/城；树叶/屋顶细节 128×128 × 4 张。
   - 全部走 `serve.js` 的 `/models/` 长缓存 + `?v=内容哈希`（与 GLB 同一条通路，SW 的 big 桶已覆盖）。
   - 颜色空间：`map.colorSpace = SRGBColorSpace`；`roughnessMap/aoMap` 保持 NoColorSpace。**新建贴图必须显式设 colorSpace**——上一轮发白就吃过这个亏。

### 4.3 阶段三：校门/地标细化（把已有 523 个资产做"精致"）

1. **法线按角度硬化**（`scripts/bake/common.py:341 build_object`）
   - 现状：`poly.use_smooth = True` 全表面平滑 → 方盒被吹圆。
   - 改为：对"倒角段"平滑、对"原始平面"保持平直——用 Blender 的 `shade_auto_smooth(angle=30°)`（4.5 的 `bpy.ops.object.shade_smooth_by_angle`）+ 必要时 `bmesh` 按面角分组。**这是本轮最省力、观感变化最大的一处**。
2. **构件细化**（`scripts/bake/gates.py` / `landmarks.py`）
   - 校门：檐口线脚、瓦垄（3~5 条连续瓦脊）、门钉、匾额边框、台阶（2~3 级）、侧灯/石狮位置、斗拱/雀替之类的小构件；柱头/柱础按风格给不同做法。
   - 地标：按类型补细节（亭子的挂落与栏杆、塔的窗与栏杆、熊猫的竹叶与肚皮分色、灯塔的栏杆与窗）。
   - 预算：`gate 6000 → 14000`、`landmark 10000 → 20000`、`prop 3000 → 6000`、`npc/player` 相应上调；三角面**仍远低于移动端阈值**（一个屏幕几十个物体 × 1.4 万面 = 可控）。
3. **顶点色 AO 加强**：`AO_STRENGTH 0.9 → 1.15`、新增"部件接缝加重"（相邻部件交界处的顶点再乘一个暗系数），并把 `AO_TINT` 从冷灰调整为**暖褐色**（参考图的暗部是暖的）。
4. **可选小贴图**：只在"读得出工艺"的地方用——瓦片（128px）、砖墙（128px）、校门匾额底纹。**匾额仍是运行时 canvas 画**（校徽是动态图，这条契约不变）。
5. **重烘与验收**：`node scripts/bake/run.mjs --kinds gate,landmark`（523 个，约 1 分钟）→ `audit-assets.mjs` → `verify-cities.mjs` → 同机位对比图。
6. 顺手把方案 §10.4 里"仍走程序化"的三类推进：**道具 36 类**（阶段二会重写其中大部分）与**词宠/玩家/NPC**（阶段一只做描边+法线硬化，全量重烘留待下一轮，理由：`js/models/auto-templates.js` 47KB 参数化造型的移植是独立的一大块，且当前词宠观感已经接近参考图的"软塑玩偶"）。

## 六、边界情况与风险

1. **性能**：MSAA+4096 阴影+描边都会吃性能。每条都留了回退档（SMAA 关、阴影退回 2048/缩小框、描边只留角色），并用 `look-shot.mjs` 的帧时长中位数卡住"不得劣于基线 5%"。
2. **触屏/老设备**：所有新增效果在 `lowEnd` 下一律不挂；GLB 与贴图的加载失败必须静默回退（`js/assets.js` 的既有契约不变）。
3. **不覆盖你另一台机器的改动**：动手前先 `git log -1` 与 `git status`，逐个文件重读后再改；你已写的注释（发白根因、ENV_ROOM_DIM、线性顶点色）原样保留。
4. **描边与拾取**：描边壳会参与射线检测 → 必须给描边壳 `userData.noPick` 或 `raycast = () => {}`（`js/game.js:3596` 的点击判定依赖 `intersectObjects`），否则点校门会打到壳上、卡片出不来。`test-fallback.mjs` 增加这条断言。
5. **贴图色域**：新贴图必须显式设 `colorSpace`（`map` = SRGB，`roughness/ao` = NoColorSpace）；这是上次发白的同类坑。
6. **描边壳的阴影**：壳不能投影，否则物体周围会出现一圈黑边阴影；壳要 `castShadow = false`。
7. **体积**：单城 8MB × 52 城 ≈ 400MB 上限（现在 30.5MB）。缓解：贴图 128~512px、复用同一张贴图包、必要时对"只有远看的小道具"用程序化不烘 GLB。审计脚本会卡这条。
8. **可读性（儿童向）**：调色后要保证"蛋/词宠/立牌"仍一眼可辨——对比度提升要优先给主体，不给背景；描边只给主体，不给地面纹理。
9. **回滚**：三条效果（MSAA、描边、调色）都是常量开关，任何一条观感不对可单独关掉而不影响其余。
