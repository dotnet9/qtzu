## 一、先报一个查证出来的真差异（这才是"不像长城"的主因）

| 事实 | 依据 |
|---|---|
| 游戏里看到的是**烘焙**那面墙 | 52/52 城都有 ground GLB；`world.js` 换装后 `procGround` 全部 `visible=false` |
| **烘焙墙从来没有砖纹** | `ground.py` 用 `clay_material('#FFFFFF')` + 顶点色（只有 AO），砖纹与砖法线只挂在程序化侧 |
| 墙顶是**一条平带** | 旧断面只有外壁/内壁/顶面三幅 |
| 烽火台是**平顶**（顶帽 + 四角垛口 + 火盆），没有屋顶 | `buildBeaconTower` 旧实现 |
| 烽火台**不被烘焙覆盖** → 屋顶不必重烘 | `world.js` 只把墙/垛口 push 进 `procGround` |

## 二、做了什么

1. **`js/wall-spec.js`（新增，共享数据层）**：12 条带的断面 + 颜色 + 垛口参数集中一处，js 与 py
   都照它生成 —— 从根上消除"两套实现各写一份数字"的漂移。实测搬数字后生成的 ground spec
   **wall 段逐字节相同**、几何字段全未变。
2. **断面**：外侧收分（底 +1.24 → 顶 +1.00）+ 条石基座（+1.40 / 高 0.42）+ 马道（±0.62，比墙顶高 0.02）
   + 压顶石 ×2（±0.72，高 0.08）+ 内侧女墙（−1.00…−0.62，高 0.55）。
   **内壁半宽 1.0 不动**（`game._cityWallMargin()` 是硬编码 1.42，动了可行走区就错）。
   砖面带与饰面带**分两组几何**：砖面带不挂顶点色（外观与旧版逐像素一致）、饰面带挂顶点色。
3. **垛口**：间距 3.4→2.2、1.05×1.0×0.38、**真箭孔**（左右两段小墙 + 下段墙合并成一个几何，
   仍是 1 个 draw call）。保留原有的 ±13% 尺寸 / ±0.35 错位 / 8% 残缺 / 逐块色差。
4. **敌楼城楼式双层檐**：底台 → 楼身 → 平座 → 下层腰檐 → 二层 → 上层正顶（每层檐用逐级收窄的
   薄板堆出凹曲屋面 + 檐口外挑）→ 正脊/垂脊（金）→ 四角起翘（8 个外旋小楔块）→ 宝顶火盆。
   高度只在 `beaconHeights()` 推导一次。实测：顶 7.82、脊 7.32、一层檐半宽 2.438 > 楼身 2.1。
5. **烘焙侧同步 + 重烘**：ground.py 按同一份 bands 扫掠；墙拆到**独立材质槽 2**（名字 `ground_wall`）；
   墙 UV 换成**真弧长**（u 0…81.24 = 周长/8，v = 断面高度比）；运行时给该材质挂与程序化侧
   **同一张**砖纹 + 砖法线，并跳过草叶颗粒细节。砖面带顶点色写白（颜色交给贴图，避免乘两遍）。
   **52 城重烘完成**：971 资产 / 251.5MB / 276 秒。
6. **接触阴影自适应**（用户并进来的那一项）：查证后更正 —— 玩家**本来就在投定向影**
   （`assets.js:128`、`models/kit.js:17` 都开 castShadow）。真正的差异是"投影 + 脚下接触阴影叠成一团"。
   改成：白天有真影子时按太阳高度角压到 0.36~0.70，夜里或低画质降级（`_fpsWatch` 关掉 shadowMap）
   给足 0.9（那时它是唯一的落地感）。

## 三、过程中修掉的六个真问题（都是校验/探针抓出来的）

1. **试烘分册覆盖正式条目**：`.cache/ground-test.manifest.json` 与正式 ground **共用资产 id**，
   合并时按类别顺序把成都的 ground 条目**覆盖**掉 → 运行时查不到 `ground` 类型 → `ground-slot` 是空的、
   换装**静默失败**。给 `run.mjs` 加类别白名单 + `--merge-only`。
2. **槽 2 的墙材质与槽 1 是同一个 Blender 数据块**（`clay_material` 按 key 缓存），导出时被去重成
   同一材质索引 → 运行时无法只给墙挂砖纹。给 `clay_material` 加显式 key。
3. **墙 UV 我最初以为能从 co.x 反推弧长**（其实 `build_one` 统一用世界 x）→ 只是换了个缩放，
   南北向墙段的砖纹仍会被拉成竖条纹。改成在 `wall()` 里直接记录环形弧长。
4. **js 与 py 的绕向相反**（js 里朝外，一直靠 `doubleSided` 掩盖）。按叉积逐面验算后统一到正确绕向，
   并加"水平面法线朝上"的断言（允许 ≤0.5% 的个别尖点：轮廓简化后可能切线反向，
   实测 8406 个顶点里 1 个）。
5. **城市模式下"走近烽火台点火"彩蛋从未生效**：`_currentStage()` 返回 game 侧 `this.islands` 的对象，
   而城市路径只把 group 记在 `this.world.islands` 上 → `st.grp` 恒为 undefined → `_updateBeacons`
   第一行就 return。修复后复测：点火成功、火苗 8.72 = 盆口 7.82 + 0.9 ✓
6. **静态文件 pipe 没有错误处理**：客户端中断下载（关标签页/截图/导航）会抛未捕获异常把本地服务弄崩
   → 浏览器报 `ERR_CONNECTION_CLOSED`、之后页面都起不来。资源变大（1.5MB → 3.9MB）后很容易触发
   （实测 check-render 连续两次失败）。两端挂 error + res close 时销毁读流。

## 五、出图与"公平对照"的方法修正

- `.cache/look/wall-close/{tower,wall,edge}.png` —— 敌楼近景（双层檐/正脊/起翘/宝顶）、墙中段
  （马道/女墙/垛口/箭孔/收分/基座）、从城内看墙
- `.cache/look/wall12/cmp-{edge,default,city}.png` —— 前后对照（左旧右新）
- **给三个出图脚本加了 `--hour`**：前后对照必须同一时刻，否则量到的是"黄金时刻"的光照差 ——
  实测 17:05 与 17:50 两次同机位截图 **87% 像素变暗**、全是光照时段差。
  钉住正午后重新对照：**26.5% 像素变化、平均亮度差 0.85%**、最大 0.682（集中在墙本身）
  → 改动是**局部的**，场景没被牵连。
- 用 `git worktree` 在改造前的提交上生成同光照对照（worktree 里 js/ 与 assets/ 是旧的，
  只把出图脚本拷过去）。
- 新增 `scripts/pix-diff.mjs`（像素对照）、`scripts/wall-shot.mjs`（三张特写）。

## 六、未做 / 已知口径

- **没让墙随地形起伏**（参考图"沿山脊蜿蜒"最壮观）。现在 `terrain-field.js` 的
  `h *= smoothstep(eFlat[0], eFlat[1], dEdge)` 是**故意**把边界压平到 0，装饰才能按 y=0 摆；
  改成山脊要同时动地形、烘焙、贴地校验与可行走区，是独立一轮的量。
- 墙高保持 3.0（用户决定），所以敌楼（到 7.8）比墙高 2.6 倍，比参考图的比例更"雄伟"。
- 没给墙加碰撞体：边界仍走 `_clampCityPos` 的多边形钳制，外侧加厚/基座**不影响玩法**。
- **内嵌浏览器面板本机仍不可用** → 观感判断来自射线扫描/像素统计；请以第五节的三张特写为准。
