## 四、阶段三：缩略图升级 + 专用打光（清晰精致）

### 4.1 分辨率与像素比

`js/models/build.js:32`：`setSize(128, 128)` → `setSize(384, 384)`；同时按 `devicePixelRatio` 提升到 `384 * min(dpr, 2)`（在高分屏上真正清晰）。

**成本控制**：384×384 的 PNG dataURL 约 120~200KB/张，932 个词宠不能全渲 —— 现状本来就是**懒渲染**（`ui.js:2300` 的 `requestAnimationFrame(fillNext)` 逐张填），所以只需把单张成本压住：
- 缩略图**不进内存缓存全部**：只保留最近 60 张（LRU），其余释放（`thumbCache` 现在是无限增长的 Map，932 张 × 150KB ≈ 140MB → **这是本轮要顺手修的隐患**）
- 词宠卡片仍用 384，但**只在可视页**渲染（分页 24 张）

### 4.2 专用打光（三点光 + 地面 + 环境）

现在只有"半球光 + 一个方向光"，所以小图平、脏、没立体感。改成：

| 灯 | 作用 | 参数（示意） |
|---|---|---|
| key（主光） | 定形、出高光 | 暖白 `0xFFF2DC`，强度 2.6，前上右 `(2, 4, 3)` |
| fill（补光） | 提亮暗部、避免死黑 | 冷白 `0xDCE8FF`，强度 0.9，左前 `(-3, 2, 2)` |
| rim（轮廓光） | 从背后勾边，把角色从背景里"拉"出来 | 亮白 `0xFFFFFF`，强度 1.6，后上 `(-1, 3, -4)` |
| ambient | 环境底 | `0xF5F1EA`，强度 0.5 |
| 地面 | 接触阴影（复用 `js/shadow.js` 的贴图） | 一张 `contactShadow` 放在脚下 |
| 环境反射 | 塑料感 | `RoomEnvironment` + `PMREM`（与游戏内一致，`envMapIntensity 0.7`） |

背景：透明（`alpha: true`）保留 —— 卡片底色由 CSS 给（金框选中时换色），这样一张缩略图能适配三种卡片状态。

### 4.3 验收

- 目视：`.cache/ui/` 里新增"角色卡 + 图鉴"截图（3 档视口）
- 结构：`verify-thumb.mjs`（新）—— 断言输出尺寸 = 384、缓存条目 ≤ 60、单张渲染耗时 < 40ms
- 性能：`look-shot` 帧时长不劣化（缩略图是**一次性**离屏渲染，不影响主循环）

## 五、阶段四：强主角（不重烘词宠）

只做主角，四件事：

1. **剪影区分**（现在男孩/女孩差异只有发型与裤子）：
   - 男孩：圆帽檐 + 短裤 + 略宽肩（`body` 横向 scale 1.04）
   - 女孩：双马尾**加长**（`0.075 → 0.095`，垂到肩）+ 裙摆（`body` 底部加一圈 `cone` 短裙）+ 略窄肩
   - 两者身高一致（`1.19`），避免"换性别 = 换体型"带来的动画错位
2. **新增 3 顶帽子**（进许愿井，价格与现有同级）：赛车头盔（呼应参考图）、小皇冠、厨师帽 —— 每顶 6~10 个图元，`player.js` 里加分支即可
3. **称号牌**：`wear.title` 现在只在排行榜显示；卡片上把它印在名字下方（已有数据，零成本）
4. **主角缩略图与游戏内一致**：卡片图直接用 `buildPlayer(gender, wear)` 的同一份几何（阶段二已保证）

**不重烘词宠**（用户明确）：词宠的 358 个 GLB 与缩略图都不动，只换渲染参数（阶段三对它们也生效，等于白拿清晰度）。

## 七、风险与边界

1. **缩略图内存**：现在 `thumbCache` 无限增长（932 张 ≈ 140MB）——本轮改成 LRU 60。**这是顺手修的隐患**，不改会随游玩时间越来越卡。
2. **384 渲染耗时**：`toDataURL` 是同步的，单张 384 约 20~40ms；分页 24 张会卡 0.5~1 秒 → 沿用现有"逐张 `requestAnimationFrame`"策略（`ui.js:2300`），不一次全渲。
3. **卡片数上限**：只显示"已拥有"的装扮组合，最多 6 张 —— 避免"看得到点不了"。
4. **换性别要重建玩家**：复用 `game.js:5187` 的既有重建路径；**玩家部件 GLB 的变体名**含性别（`playerVariantTag`），所以换性别必须重跑 `applyParts`（否则戴的是上一个性别的部件）。`verify-charsel.mjs` 会断言这一点。
5. **不动词宠资产**（用户明确）；不动 `PROPS`/`parts` 既有契约；`#charsel` 用动态建面板，不改 `index.html` 的大段结构。
6. **镜头跟随的"转圈"风险**：靠 60° 死区 + 只在走路时跟 + 缩放 >45 不跟 三重约束；`verify-cam.mjs` 会断言"连续走路 3 秒内 `camYaw` 不会持续自转"。
7. **本轮不含**：⑨ 跳跃挑战引导（上轮遗留）、⑪ 天空体积云 + 后处理（上轮遗留）—— 它们与本轮无耦合，留待下一轮。
