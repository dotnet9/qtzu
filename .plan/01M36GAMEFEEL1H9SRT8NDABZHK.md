## 二、① HUD 游戏化：参考图的语言

- `#hud-left` = 用户名 + `#hud-col`（列：**主进度条** / 章节小字 / **词宠头像栏**）
- `#hud-right` = `#hud-chips`（饥饿 / ⭐ / 🏆 / 🔥 四枚色块）+ 节日徽标 + 🪄 + ☰
- 进度条 = 深槽 + 糖果渐变填充 + **条内数字**；词宠头像栏最多 6 格，**已孵化的排到最前**
  （像参考图"已拥有的技能在前"），未孵化为虚线空槽，新孵化那一格蹦一下

**两条不能动的约束**（改了会静默坏掉，已逐条钉进校验）：
1. `#pet-count` / `#star-pill` 是 `homePaw` / `homeStars` 的**归航飞行目标**，`#star-pill` 上还挂着 click
   → 五个锚点 id 与可见尺寸全部保留
2. 三处写入者原本 `textContent = …` 会**清空容器**（把新加的填充层/图标擦掉）
   → 改为写内层 span：`#pet-count-text` / `#star-pill-num` / `#score-pill-text`

**校验抓出的布局回归**：左列改成列方向后 `#user-pill` 叠在进度条上方，把左列撑到 133px →
城市胶囊（96px）撞上 `#hud-chapter` 与 `#pet-icon-bar`。诊断脚本打出真实矩形后定位，
改为"用户名 + `#hud-col` 列"，左列回到 78px，城市胶囊下移到 102px（手机 92px）。
另外手机档残留旧规则的 `margin-left:-3px` 让进度条偏出父容器 3px，一并清掉。

## 三、② 脚下指示环：颜色是"现在能做什么"

`js/ring.js`：`TorusGeometry(0.5, 0.045)`，`depthWrite=false / fog=false / toneMapped=false / noPick`。
颜色按**操作方式**分三类：蛋=暖金（走过去）/ 台阶与云梯=薄荷（跳上去）/ 台顶奖杯=紫（踩上台面）/
无目标=柔白且降到 32%。最近者优先，6 米外退回柔白；奖杯只在 `_jumpReached≥1` 后提示。
目标搜索每 9 帧算一次。

**修掉**：环的抬升 0.02 其实**低于**接触阴影（`js/shadow.js` 自身抬升 0.035）→ Δy=-0.015，环会被阴影盖住。
改成 0.055（阴影之上 2cm）。校验自身也修了一处：随手取 `eggs[0]` 正好在台阶旁边，而规则是"最近者优先"。

## 四、③④ 地面：先更正我自己的两处误判

提方案前我说过"城市地面**完全没有铺装**，只有 4 个方位椭圆色块"——**错的**。
52/52 城都有 `terrain.json`，全走真地形引擎，`terrain-field.js:340` 起就在画主街+缘石+广场。
真正的缺口是**材质层**：区域色是平涂，没有石板缝/裂缝/苔藓/车辙。

- **斑驳光影**：n2 低频噪声乘亮度、不动色相，亮部 +8% / 暗部 −16%
  （亮部幅度必须小于暗部 → 净效果略变暗，不把草地亮度上界 0.70 往上推；乘性调制不改饱和度）
- **铺装材质层**：石板缝 2.2 米格 / 缝宽 10cm、裂缝（高频脊线）、苔藓（缝附近 × 潮湿噪声 → 冷绿）、
  车辙（主街中心两条平行暗带）
- **只改 `zoneColor` 一处**：顶点色路径与贴图路径都是它的调用者 → 自动同源（校验：最大差 0/255）

**校验抓出的一个真设计错误**：n2 的三项本身是 48/118/88 单位周期，我最初乘 0.8 是把它变得更**慢**
（60~148 单位，比整座城还大）→ 光斑退化成整体渐变，画面变化度反而**降了 1.6%**。
必须乘大：光斑 ×11（周期 4.4/10.7/8.0 单位）、裂缝 ×34、苔藓 ×5。

**判据也是我最初写错的**：用"整城亮度标准差提升 ≥20%"永远过不了 —— 整城方差被大尺度色带
（深绿→浅绿→雪线）主导，sd 0.0765 里几乎没有局部成分。改用**局部对比度**（5×5 邻域偏差的 RMS）：
0.02189 → 0.02598（+18.7%）✓

**性能**：光斑逐像素算 3 次三角函数太贵（1024² 总生成 350ms）→ 改 256² 查表 + 双线性
（光斑是 4~10 单位的平滑场）→ **294ms**，其中我的新增部分约 35~45ms。
方案里">150ms 就降 768²"针对的是**增量**，未触发（那个 150ms 是我拍脑袋的估算，老代码本身就 ~250ms）。

## 五、⑤ 前景枝叶 + 边缘压暗

`js/foreground.js`：8 片枝叶剪影挂在**相机坐标系**（转视角时跟着滑），
`depthTest:false` + `renderOrder 900`（永远最上层、不穿模）、固定种子（截图可复现）、触屏不建。
**尺寸按"中央 70% 必须干净"反推**：面片旋转后轴向半跨度 ≤ (s/2)·1.41，取 s = 0.40×画面半高、
rot ≤ ±0.5 rad → 内伸 ≤13.7%，中央干净带从 15% 开始。
**暗角 0.32 → 0.42**：枝叶只是四边的点状遮挡，压边要靠暗角。

**校验自身写错的断言**：原来分别看 x/y 的"内伸量"，对"贴上边但水平居中"那片误报 56%
（它在 x 上确实到画面中央，但在 y 上完全在画面外）→ 改成**屏幕矩形与中央 70% 盒求交**。
